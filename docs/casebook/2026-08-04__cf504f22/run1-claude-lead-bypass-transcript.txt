     ## Tools

     ### claude

     Non-interactive invocation, prompt over stdin:

         claude -p --model <model> --output-format json --permission-mode bypassPermissions

     `--permission-mode bypassPermissions` avoids a headless call blocking on an
     approval prompt no one is present to answer. Add `--effort
     <low|medium|high|xhigh|max>` (default `high`) to trade cost against depth
     without changing model.

     #### Identification

     Add `-n <name>` to name the session — shown in `/resume` and searchable in
     its transcript, so it can be found again later. The result JSON's
     `session_id` field also resumes it directly via `claude --resume <id>`.

     ### codex

     Non-interactive invocation, prompt over stdin, result written to a file:

         codex exec --model <model> -s danger-full-access -o <output-file>

     `-s` is codex's sandbox/approval policy (`read-only`, `workspace-write`,
     `danger-full-access`) — `danger-full-access` is used here so a headless call
     never blocks on an approval prompt no one is present to answer. Add `-c
     model_reasoning_effort=<level>` to trade cost against depth without changing
     model.

     Codex model IDs use dots, not dashes — e.g. `gpt-5.6-sol`, not
     `gpt-5-6-sol`.

     #### Identification

     Identified by the session id it prints at the start of a run (`session id:
     ...`); resume it with `codex resume <id>`.

     ## Models

     Four axes rather than one blended score — these models trade places
     depending on task shape, and a single number would hide that:

     - **Depth** — can it crack a hard, ambiguous, or novel problem?
     - **Execution** — can it drive a long agentic/terminal loop through
       well-specified work efficiently?
     - **Cost-to-task** — realistic cost to get a representative task *done*,
       not price per token.
     - **Fidelity** — does it do what was asked and report honestly,
       unsupervised? "Untested" means no evidence either way, not a neutral
       default.

     Ratings are coarse and relative, not benchmark scores.

     | tool | model | depth | execution | cost-to-task | fidelity | notes |
     | --- | --- | --- | --- | --- | --- | --- |
     | claude | claude-opus-5 | 5 | 4 | high | no flags found | current flagship; complex code, architecture, orchestration. Peaks

     ## Notes

     - Effort/reasoning level (`--effort` / `model_reasoning_effort`) trades cost
       against depth without switching models — try that before escalating.

     - Cost-to-task reflects actual usage, not sticker price — `claude-sonnet-5`
       is priced low but can cost more per finished task than Opus at high effort.

     ## Findings

     ### Major — Redundant/verbose accessible name on the site logo, repeated on every page
     **File + location:** `index.html`, `about.html`, `links.html`, `guestbook.html` — `<svg class="brand-mark" ... role="img"
     aria-label="A pixel-art fish">` inside `.brand` (header, all 4 pages).

     **Problem:** The pixel-fish SVG is given `role="img"` + `aria-label="A pixel-art fish"`, but it sits directly inside the same `<a
     class="brand">` as the visible text "Dave's Homepage / my little corner of the web, since 1999". A screen reader announces the
     link's full accessible name as the concatenation: *"A pixel-art fish, Dave's Homepage, my little corner of the web, since 1999,
     link"* — on **every single page**, since this is the home link in the shared header. The icon conveys no information the adjacent
     text doesn't already state; per WCAG 1.1.1 this is a textbook case for an empty/no accessible name. Notably the implementation gets
     this *right* elsewhere (`card-icon`, `theme-toggle-icon`, webring SVG are all correctly `aria-hidden="true"`), so this is an
     inconsistency, not a stylistic choice.

     **Suggested fix:** Change to `aria-hidden="true"` and drop `role="img"`/`aria-label` on `.brand-mark`, matching the treatment
     already used for `.card-icon` and the webring SVG.

     ---

     ### Minor — Skip link target is not programmatically focusable
     **File + location:** All 4 pages — `<a class="skip-link" href="#main">Skip to content</a>` targeting `<main class="site-main"
     id="main">`.

     **Problem:** `<main>` has an `id` but no `tabindex`. In several browser/AT combinations, activating a fragment link to a
     non-focusable element scrolls the viewport but does not reliably move keyboard focus there, so a subsequent Tab press can resume
     from the top of the document rather than from where the user landed — defeating the purpose of the skip link for keyboard-only
     users.

     **Suggested fix:** Add `tabindex="-1"` to `<main id="main">` on all four pages so focus lands predictably. (Optionally suppress the
     resulting focus ring on `main` specifically if the visual is undesired, but keep it focusable.)

     ---

     ### Minor — External-link arrow relies on a CSS "alt text" syntax with poor browser support
     **File + location:** `styles.css` line ~586, `.link-list .external::after { content: " ↗" / ""; ... }`

     **Problem:** The `content: <string> / <string>` (alt-text-for-generated-content) syntax is Chromium-only today. In engines that
     don't parse it (Firefox, Safari), the whole `content` declaration is invalid CSS and is dropped — meaning the "↗" external-link
     indicator simply never renders in those browsers, rather than degrading gracefully with a suppressed-but-present glyph as
     presumably intended. Worth knowing this "a11y-safe icon" doesn't actually behave consistently across browsers, functionally or
     visually.

     **Suggested fix:** If the arrow is purely decorative, a simpler and universally-supported approach is fine (plain `content: " ↗";`
     with no alt override — arrow characters read by AT as junk are a much smaller cost than an icon disappearing outright in half of
     browsers), or move the glyph into the HTML as `<span aria-hidden="true"> ↗</span>` next to each external link title for guaranteed
     cross-browser behavior.
